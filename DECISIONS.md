| O24 | **Role resolution precedence + one resolver.** Fleet assignment runs through a single `workflow::roles_resolve::provider_for(role, idx, fleet, cfg)` with fixed precedence **explicit `--providers` (positional one-off) > `[roles]` > `[providers].order`**. | O26 | **A run has one base commit, taken from the invoking directory.** Slot worktrees are cut from `state.base_commit`, resolved once at run creation as `--base <ref>` (branch/tag/sha/`origin/main`; unresolvable = hard error, never a silent fallback) else the HEAD of the cwd spar was invoked from. Not `project_root`'s HEAD: `find_project_root()` deliberately maps a linked worktree to the main checkout so `.spar/` stays one per repo, which meant the documented one-agent-per-worktree setup handed every slot the main branch while the run looked healthy. Recorded as `base_ref`/`base_commit` in `state.json`, run JSON and `status --json`, and printed at launch — a wrong base has to be *visible*, since agents on the wrong branch report cleanly and find nothing. `implement --run <id>` inherits it; a run **cannot be re-based** after creation (the plan phase's frozen tests are overlaid wholesale into the implementer, so straddling two bases yields a branch parented on the new base carrying the old base's contents) — plan a new run instead. `ship` targets its draft PR at the run's base branch when that branch exists on `origin`, else the repo default, overridable with `ship --base` | DECIDED |
| O27 | **A run is bound to the config it was created with.** `spar.toml` is one mutable file at the project root (the main checkout) read fresh by every process, while only `isolation`/`autonomy`/`message_budget`/`providers` were snapshotted into `state.json` — so `[roles]`, `[timeouts]`, `[spec]`, `[suite]`, `max_agents` and `[review].require_all_criteria` were live reads, and `implement --run` re-resolved the fleet from whatever the file said at resume. With one agent per worktree all sharing that file (and the operator policy telling agents to write `[roles]` into it before launching), concurrent runs silently re-configured each other, up to and including loosening another run's ship gate. Each run now freezes the merged config at creation into `.spar/runs/<id>/config.json`; every run-scoped command reads the snapshot, never the live file. `implement --reload-config` is the only escape hatch and re-freezes rather than bypassing. `--role <role>=<provider>` (repeatable) assigns per role on the command line so agents never need to write the shared file at all — it is the reason they were writing it, since `--providers` is positional only. Precedence: `--providers` > `--role` > `[roles]` > `[providers].order`. Pre-O27 runs fall back to the live file. Deliberately out of scope: the TUI's stall *display* thresholds still come from the project config, since it renders many runs across projects and per-run config I/O per frame buys nothing — run execution is unaffected | DECIDED |
| O28 | **Abandoned runs are surfaced and swept, never auto-reaped.** Slots spawn into their own process groups (so slot timeouts reap nested suites), so they outlive their orchestrator: a driver's command timeout leaves agents running with nobody collecting their work. Four pieces: `wait` returns exit `3` once a run reads abandoned for a grace window (15s, `SPAR_ABANDON_GRACE_SECS`) instead of blocking to its timeout on a run that can never advance; `status --json` carries `orphan_pids`; `spar stop --abandoned` sweeps a project; and SIGINT/SIGTERM to an orchestrator signals its slot groups, then **restores the default disposition and re-raises** so spar still dies on the operator's signal rather than surviving it and reporting a later phase as the run's outcome. Rejected: reaping automatically from any spar invocation — `status` is observe-only by contract, and a human driving a slot through the TUI holds no run lock, so their run reads abandoned too; killing tokens is cheap, killing a live session is not. SIGKILL is uncatchable, so the sweep is the backstop, not the handler | DECIDED |
| O29 | **Worktree reclamation is a sweep, and rejection reaps immediately.** Nothing reclaimed worktrees: `auto_cleanup` defaults false, the auto-clean it gates only fires for `Phase::Done` reached inside `maybe_auto_ship_or_cleanup`, and the normal successful path ends at the **ship gate** instead — so even successful runs accumulated one worktree per slot forever, and `spar cleanup` needed an explicit run id (75 stale worktrees across three projects on the author's box). `spar cleanup --all` now sweeps runs nothing can resume (`done`, `plan_rejected`); `--older-than <dur>` extends it to resumable-at-rest runs (`stopped`/`failed`/`stuck`/`quota`/gates) whose age is the evidence nobody is returning. In-flight runs are never swept whatever their state file says — parking them is `stop`'s job. `spar reject` reaps its run's worktrees inline, since `implement --run` requires an approved plan and a rejected one can never be resumed; artifacts stay. Rejected: flipping `auto_cleanup` to true, which would delete resumable work by default | DECIDED |
| O30 | **The spec overlay carries git-visible files only, and says what it left behind.** `apply_spec_tests_to_impl` walked the test-author worktree unfiltered and byte-copied everything but `.git` into every implementer, so `target/` and `node_modules/` crossed worktrees — gigabytes per slot, on a run still reporting phase `prepare_isolation` (measured: one run blocked >60min in state `D` on `blk_mq_get_tag` with an fd open on `target/debug/.fingerprint/`; impl worktrees reached 54 GB). The overlay now enumerates via `git ls-files --cached --others --exclude-standard`, falling back to the walk only where git lists nothing (the dry-run cwd under an ignored `.spar/`) and saying so when a git *error* forces that fallback, since the walk is the gigabyte copy and must never resume silently. What git ignores therefore no longer crosses — including fixtures a test-author wrote into an ignored path (`.env.test`, an ignored `tests/data/`) — so the overlay **reports** them: the ignored entries (directories collapsed, so `target/` is one line) go to stderr, the event log, the bus, and the implementer's own prompt with the author worktree path and an instruction to copy across what a test needs and to leave build output alone. Silence was the alternative, and it surfaces as an acceptance test failing at runtime for no visible reason, against an implementer explicitly permitted to weaken a test if it documents why. **Rejected: hardlink-seeding build output into slot worktrees** (`cp -al target`, briefly shipped as `[worktree] seed_dirs`). The premise — "cargo replaces outputs rather than rewriting them in place" — is false. Cargo rewrites `target/debug/.fingerprint/*` in place and decides freshness by mtime, so sharing those inodes means one slot's build bumps every other slot's fingerprints; the next slot reports `Fresh`, compiles nothing, and its `target/debug/<bin>` is still the hardlink to the project's binary. Reproduced independently twice: a slot's own change never compiled, exit 0, and the implementer smoke-check plus the authoritative suite then run against a binary without the change. `incremental/` was the wrong exclusion. Two further defects made it unsalvageable in that form: `.cargo-lock` is hardlinked and `flock` is per-inode, so the seed reintroduces exactly the fleet-wide build serialization this entry cites as its reason for rejecting a shared `CARGO_TARGET_DIR`; and `cp -a` implies `-d`, so a symlinked `target/` is copied as a symlink, giving every slot one shared dir and making the `incremental/` cleanup delete outside the worktree. A COW copy (`--reflink=auto`) would give real inodes and is the only version worth revisiting. Also rejected, unchanged: a shared `CARGO_TARGET_DIR` across slots | DECIDED |
| O31 | **A clean exit with work on disk and no artifact is recoverable, not failed.** Slots that backgrounded a long build, spent their remaining turns polling it, and exited 0 without a summary were failed on `missing expected artifact`, throwing away a complete implementation plus its build and re-dispatching from scratch (~45min once). The gate now grants one artifact-only recovery turn (600s, "write this file, run nothing, change nothing else") when the slot's worktree holds commits past `base_commit` or a dirty tree. A worktree with nothing in it still fails — the recovery is for a missing write-up, never for missing work. **Implementer only**, and that restriction is load-bearing: `tester` and `reviewer` slots are pointed at the *implementer's* worktree, so "has work" is true for them whether or not they did anything, and the recovery agent is a fresh session with no memory of the turn it is summarizing. A recovered `suite.md` reading `## Result: pass` would set the authoritative gate green with no suite having run; a recovered `test-contract.md` would carry no `AC-n`, so `parse_contract_criteria` yields nothing and `acceptance_blocks_ship` goes vacuous — a green run with nothing holding it. Those roles keep failing closed into the existing salvage path, where a human sees them. Recovery also gets its own `<slot>.recovery.log` (reusing the slot log would truncate the transcript of the turn that did the work, which is both the operator's only diagnosis and what `salvage_expected_artifact` tails), and is spawned with the same pid marker and liveness beat as any other slot, so `stop --abandoned` can see it and a long recovery cannot let a live holder's path reserves lapse. Paired with the prompt fix: `implementer` and `test_author` now carry the foreground-only rule `tester` already had, since the slots did not know a multi-hour `slot_secs` meant they could just block | DECIDED |
| O32 | **The suite gate reports its own coverage gaps; it never closes them.** The tester writes its own command list, so an implementer that adds a test binary the list does not name gets a green authoritative gate that never compiled the code written to prove the change (observed; a reviewer caught it, the harness could not). spar now diffs added test files against the parsed `## Commands` and appends a `## Coverage warning` to `suite.md` (plus an event and a bus broadcast) — into the reviewers' input, where judgment lives. It does **not** fold the missing targets into the command list: a harness that rewrites its own gate is not a gate. Suppressed unless the commands are *selective*, because a command that runs the project default compiles everything and warning there would fire every run and train the operator to ignore it. Selective means an explicit target flag (`--test`, `--bin`, `--lib`, `mod::case`) or a named test *file* argument. Deliberately **not** selective: `-p`/`--package` (`cargo test -p foo` builds every test target in `foo`, including one added this round), directory arguments, and anything past a pipe or `&&`. An earlier form counted any token containing `/` and so warned on `pytest tests/`, `go test ./...` and `./scripts/test.sh` — the canonical full-suite command of three ecosystems, i.e. exactly the false-positive class this suppression exists to prevent | DECIDED |
| O33 | **`roles`, not `providers`, is the answer to "what is running this".** `state.providers` is the run's pool; printing it at launch and in `status` showed operators providers they had deliberately excluded by role. Launch lines and `status` (human + `--json`) now report the resolved `role=provider` assignment read off the dispatched slots, reviewers joined with `+`; the plan launch line moved after slot resolution to have something to report. `providers` stays in the JSON as the pool. Same reasoning applied to `cleanup --all`, which now prints each **spared** run with a reason (resumable / below `--older-than` / in flight) instead of "nothing to sweep" beside gigabytes of finished worktrees | DECIDED |
| O34 | **Merged is evidence, and it reclaims on its own.** O29 accepted only *age* as evidence that a resumable-at-rest run was garbage, so a run that shipped and landed still had to out-wait `--older-than` while its worktrees held tens of gigabytes (124 GB across a handful of runs, on a box where tmpfs and page cache are already contended). Containment in the run's own `base_ref` is stronger evidence than age — the work is in the base branch — so `cleanup --all --merged` reaps at-rest runs whose every slot branch is an ancestor of their base, and `[worktree] auto_cleanup_merged` (default **true**) runs that same sweep automatically just before a launch cuts new slot worktrees, reporting what it reclaimed and never failing the run. Default-on is the reverse of O29's call on `auto_cleanup` and deliberately so: `auto_cleanup` deletes resumable work off a *phase check*, this deletes only what git says is already merged. **Ancestry alone is not the test.** A slot that wrote code and never committed leaves its branch sitting on the base, which is trivially an ancestor, so ancestry by itself reports "fully landed" for exactly the work most at risk — and `cleanup_run` removes worktrees with `--force`. Reproduced: a run parked at the plan gate with uncommitted acceptance tests was reaped by an unrelated `spar plan`, taking the tests with it and leaving the run unresumable. So a worktree with **uncommitted changes** vetoes the verdict, failing closed when git cannot answer. Two further guards on the sweep: it skips runs whose orchestrator is alive (the phase on disk is a snapshot, and a resuming process is briefly between load and save — reaping there also terminates that run's agents, since `cleanup_run` kills processes whose cwd is inside), and it skips runs with no worktree left on disk (records outlive their worktrees, so without it every launch re-ran `worktree remove` / `branch -D` / `prune` and re-reported reclaiming what it already had). In-flight runs are untouchable; `at_rest` is necessary, not sufficient. Deliberate limitation: containment is **ancestry**, so a **squash-merged** branch reads as unmerged and needs `--older-than` or an explicit run id — the safe direction to be wrong in, since the alternative (patch-id matching) deletes work that only looks landed. Base resolves local-first, then `origin/<ref>` | DECIDED |
| O35 | **Archiving is presentation; cleanup is lifecycle.** `cleanup` reclaims worktrees and deliberately keeps `.spar/runs/<id>` — that is where `plan.md`, `test-contract.md`, the reviews, `suite.md` and `stats.json` live — so nothing ever removed a *record*, and a CLI-driven project accumulated one listing row per run forever (payforge: 69 rows, of which 28 `done` and 4 `plan_rejected`, with **12 runs parked at a gate** buried among them). The answer is a third state between listed-forever and deleted: `archived_at` on the run, hidden from `status` and the TUI rail, shown by `status --archived`, reversible with `archive --undo`, and deleting nothing. Filtering happens at the *listing surfaces*, never inside `list_runs` / `list_all_runs`, because resolving a run by id has to keep reaching archived runs — archiving hides a run from browsing, it does not retire the id. Three rules keep it safe on by default (`auto_archive_after = "14d"`): only `done` / `plan_rejected` auto-archive, never a **gate** (hiding the runs that want a human is the failure this feature exists to prevent) and never the ambiguous `stopped`/`failed`/`stuck`/`quota`; a run stays archived only while its phase stays *archivable* (`done`/`plan_rejected`), so resuming, re-approving or parking at a gate all restore it — keyed off the archivable set rather than `at_rest`, because `spar approve` accepts a `plan_rejected` run and moves it to `PlanApproved`, which is inside `at_rest`, leaving an approved run hidden while it waited for `spar implement`; the manual-archive refusal likewise gets its own `archivable_by_hand` predicate so a pending change to the sweep's notion of rest cannot silently alter what may be archived; and the sweep fires at **launch** only, never from `status`, keeping read commands observe-only (same rule as `stop --abandoned`). `save()` does not touch `updated_at`, so archiving preserves a run's true age and `cleanup --older-than` still sees it | DECIDED |

## TUI

TUI restructure (2026-07-14). See `roadmap/tui-redesign-plan.md` for the staged build.

| ID | Decision | Status |
|----|----------|--------|
| U1 | TUI is a **rail + one main area** (content = f(selection × tab)), not N co-equal Tab-cycled panels. Rail is a `projects ▸ runs ▸ agents` drill-down (`Enter` pushes, `Esc` pops, breadcrumb in a single status line); Log/Activity/Diff/Shell are **tabs over Main**. Focus targets cut 6 → 3 (Rail/Main/Composer) with direct keys `1/2/3`. Chrome cut from 10 rows to 2. Researched against k9s / lazygit / lazydocker / herdr / claude-squad, which all use this shape; an N-way focus ring destroys spatial memory | DECIDED |
| U2 | The embedded terminal is a **mode, not a panel** — it lives in Main's Shell tab (Stage A) and becomes a full-screen Driving mode (Stage B). Escape is a prefix (`C-a`) + `F12`, never `Esc`/`Tab` (the agent needs those — Shift+Tab is Claude Code's permission toggle) | DECIDED |
| U3 | Stage B: the `:` **command palette replaces the Composer focus target** — focus is 2-wide (Rail/Main, keys `1`/`2`); the palette is a transient overlay, not in the ring. Its verbs are the run-lifecycle actions the orchestrator already brokers (`approve`/`reject`/`ship`/`confirm`/`reconcile`/`takeover`/`spawn`/`chat`) plus `implement`/`plan`, which spawn the detached CLI **reusing the selected run's recorded `providers`** — a fresh fleet needs a provider picker a text palette can't offer, so those error to the CLI. All complete run ids from the roster | DECIDED |
| U4 | Stage B: **`q` is the quit path**; double-`Ctrl+C` retired so `Ctrl+C` is unambiguously the agent's SIGINT in the Shell tab. `/` filters the rail (dim-in-place + match-only navigation; hiding rows would desync the selection index that feeds the snapshot). Diff renders the selected slot's real `git diff HEAD`, capped, falling back to artifacts when a slot has no worktree | DECIDED |
| U5 | Stage C: **attention model.** Each run gets a cheap `Attention` level from its summary (`Gate > Broken > Working > Idle`); the rail is **attention-sorted** (loudest first, then recency) with selection **glued to the run id** across re-sorts. A run that wants the operator flies a `⚑` and rolls up to its project row and a status-line `⚑N need you` count. **`a` jumps to the next run that needs you** (approve loses its one-key shortcut — tap the button or `:approve`); tapping the roll-up does the same. A run crossing into Gate/Broken **toasts** (first snapshot primes silently). Width bands: `<80` Main-only · `80–119` rail+Main · `>=120` the extra width goes to Main, never a 4th box | DECIDED |
